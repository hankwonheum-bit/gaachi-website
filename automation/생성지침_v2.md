# Step 1 — 대상 선정

`automation/sources/inventory_v1.tsv` 의 컬럼 순서(1-base)는 다음과 같습니다. **컬럼 번호를 착각하지 마십시오.**

```
1 seq   2 file_id   3 purpose   4 region   5 dong   6 prop_type
7 base_date   8 value_krw   9 methods   10 status   11 src_path   12 notes
```

→ `status` 는 **10번**, `notes` 는 **12번**입니다. (`$9` 는 `methods` 입니다.)

**선정 규칙**: `status == PENDING` 이고 `notes` 에 `부적합` / `UNSUITABLE` 이 없는 행 중 `seq` 가 가장 작은 1건.

awk 한 줄:

```bash
awk -F'\t' 'NR>1 && $10=="PENDING" && $12 !~ /부적합/ && $12 !~ /UNSUITABLE/ {print; exit}' \
  "$HOME/mnt/gaachi-website/automation/sources/inventory_v1.tsv"
```

python 한 줄(같은 결과, 컬럼별 라벨 출력):

```bash
python3 -c "import io,sys; p='$HOME/mnt/gaachi-website/automation/sources/inventory_v1.tsv'; L=[l.rstrip('\n').split('\t') for l in io.open(p,encoding='utf-8')]; H=L[0]; R=[r for r in L[1:] if len(r)>=12 and r[9]=='PENDING' and '부적합' not in r[11] and 'UNSUITABLE' not in r[11]]; R.sort(key=lambda r:int(r[0])); print('\n'.join('%-10s %s'%(h,v) for h,v in zip(H,R[0])) if R else '대상 없음')"
```

- 대상이 없으면 "게시 가능한 PENDING 사례가 없습니다" 라고 보고하고 종료합니다.
- `notes` 에 `미추출:` 항목이 적혀 있으면 **그 항목은 PDF 에서 직접 확인해야 하는 값**이라는 뜻입니다.
  확인이 불가능하면 이 행을 건너뛰지 말고 **중단하고 사용자에게 보고**하십시오
  (임의로 다음 seq 로 넘어가면 우선순위가 무너집니다).
- `notes` 에 `1건만 게시 권장`, `동일 기준시점` 같은 문구가 있으면 그 지시를 따릅니다.

# Step 2 — PDF 판독

**원본 PDF 는 전부 스캔 이미지입니다. 텍스트 레이어가 없습니다.** `pdftotext` 는 빈 결과를 냅니다.

## 2-A. 권장 경로 — 이미지로 변환해 Read 툴로 눈으로 읽기 ★

**감정평가표와 비교사례 표는 반드시 이 경로로 읽으십시오.** OCR 은 표의 자릿수·쉼표·㎡ 단위를
일상적으로 망가뜨립니다. 숫자가 틀린 페이지가 게시되는 것이 이 파이프라인 최악의 실패입니다.

1. PDF 를 컨테이너로 가져옵니다.
   `mcp__remote-devices__device_stage_files` 에 `paths` 로 PDF 의 절대경로를 넘기면
   `/mnt/user-data/uploads/...` 아래에 복사되고, 그 경로를 결과가 알려 줍니다.
2. 그 경로를 **Read 툴**로 `pages: "1-6"` 처럼 페이지를 지정해 직접 읽습니다(한 번에 최대 20페이지).
3. 표는 화면에 보이는 대로 옮겨 적고, 숫자는 **한 자리씩 소리 내어 확인하듯** 대조합니다.

페이지 이미지가 더 필요하면 아래처럼 PNG 로 뽑아 Read 로 봅니다.

```bash
mkdir -p /tmp/pg && \
pdftoppm -r 150 -gray -f 1 -l 6 -png \
  "$HOME/mnt/홈페이지 개설/신규홈페이지/감정서 샘플/<파일명>.pdf" /tmp/pg/p && ls -la /tmp/pg
```

## 2-B. 보조 경로 — OCR (검색·위치 파악용, 숫자 확정용 아님)

```bash
# 1) 한국어 학습데이터 확인 (없으면 다시 받는다 — /tmp 는 세션마다 비워질 수 있음)
ls /tmp/tessdata/kor.traineddata 2>/dev/null || { \
  mkdir -p /tmp/tessdata && \
  curl -L -o /tmp/tessdata/kor.traineddata \
    https://github.com/tesseract-ocr/tessdata/raw/main/kor.traineddata ; }
TESSDATA_PREFIX=/tmp/tessdata tesseract --list-langs   # eng, kor, osd 가 나와야 함

# 2) 1~6쪽을 150dpi 흑백 PNG 로 변환
mkdir -p /tmp/pg && pdftoppm -r 150 -gray -f 1 -l 6 -png \
  "$HOME/mnt/홈페이지 개설/신규홈페이지/감정서 샘플/<파일명>.pdf" /tmp/pg/p

# 3) 페이지별 OCR
for f in /tmp/pg/p-*.png; do
  echo "===== $f ====="
  TESSDATA_PREFIX=/tmp/tessdata tesseract "$f" stdout -l kor --psm 6 2>/dev/null
done
```

- 150dpi 에서 흐리면 `-r 300` 으로 올립니다(느려지지만 정확도가 올라갑니다).
- `--psm 6`(균일한 텍스트 블록)이 감정평가서 레이아웃에 가장 잘 맞습니다. 표가 깨지면 `--psm 4` 를 시도합니다.
- **OCR 결과의 숫자는 그 자체로 신뢰하지 않습니다.** 위치를 찾는 데만 쓰고,
  값은 반드시 2-A 의 페이지 이미지로 눈으로 확인한 뒤 확정합니다.

## 2-C. 숫자 이중 확인 (예외 없음)

아래 값은 **초안에 쓰기 직전에 페이지 이미지와 1:1 로 다시 대조**합니다.

- 최종 감정평가액 (원 단위 전액)
- 기준시점 (**연도**. 월·일은 페이지에 쓰지 않지만, 평가기간 판단을 위해 읽기는 합니다)
- 감정평가서 작성일 (표지 기재일 — **페이지에 월·일까지 씁니다**)
- 토지면적 / 건물 연면적 / 전유면적 / 공용면적 / 대지권면적 (㎡, 소수 둘째자리까지)
- 산정단가·결정단가 (원/㎡)
- 사정보정치, 시점수정률
- 사용승인일

대조 결과는 `inventory_v1.tsv` 의 `base_date`·`value_krw` 와도 맞춰 봅니다.
**inventory 값과 PDF 값이 다르면 PDF 가 우선**이며, 그 사실을 Step 9 로그의 `note` 에 남깁니다.
둘 다 불확실하면 그 사례는 만들지 말고 중단합니다.

| 본건 호수 | **항목 삭제** | `호수` 라벨을 만들지 않음 |
| 본건 면적(전유·공용·합계·대지권·토지·연면적) | **그대로 기재** | 숫자는 살린다 |
| 본건 소재지 — 집합건물 | **동 + 지번까지** | 예) `서울특별시 강남구 개포동 654외 1필지` |
| 본건 소재지 — 토지·일반건물 | **동까지만** | 예) `서울특별시 강동구 성내동`. 지번 금지 |
| 도로명주소 | **금지** | 물건 종류 불문 |
| 기준시점 | **연도만** | `2025년` / `<time datetime="2025">` |
| 감정평가전례·거래사례 소재지 | **동 단위까지** | 지번·**동 번호**·층·호 모두 삭제. 표에 해당 열을 만들지 않음 |
| 감정평가전례·거래사례 시점 | **연도만** | `2025년` |
| 감정평가전례 목적 | `—` 처리 | |
| 시점수정 지수 적용 월 | **금지** | 지수명 + 최종 시점수정률만 |
| 가치형성요인 비교치 | **미게재** | 표·요인치 전부 |
| 보고서 번호(HQ2025x-xxxxx) | **표시 안 함** | |
| 감정평가서 작성일 | **기재(월·일까지)** | 개인정보 아님. 별도 항목 |

**왜 기준시점이 연도만인가**: 상속 사건의 기준시점은 상속개시일(피상속인 사망일)이라 그 자체가 개인정보이며,
단지·면적과 결합하면 유족이 특정될 수 있습니다. 목적별로 규칙을 나누면 상속 건만 눈에 띄므로 **전 목적 공통**으로 연도만 씁니다.

# Step 5 — 템플릿 채우기 (v3 개정)

1. `templates/case_template_v3.html` 을 **복사**합니다. 원본은 절대 수정하지 않습니다.
2. `templates/필드정의_v2.tsv` 를 옆에 놓고 `{{TOKEN}}` **114개**를 전부 치환합니다.
   각 토큰의 `마스킹규칙` 열을 반드시 읽고 적용합니다. TSV 의 행 순서는 템플릿 출현 순서와 같습니다.
3. **선택 블록은 빈 값으로 두지 말고 블록 전체를 삭제합니다.**
   - `METHOD3_*`, `METHOD4_*` — 해당 평가방법을 언급하지 않을 때(`method-item` div 통째로)
   - `CALC_GROUP2_*` — 단일방법(집합건물 일괄평가 등)일 때(`h3` + `calc-flow` 통째로)
   - `RESTRICT_ALERT` — 특별 제한이 없을 때(`restrict-alert` div 통째로)
   - `MENTION_4` — 관련 주제가 3개뿐일 때(JSON-LD 객체 한 줄 통째로, 앞 줄의 콤마 정리)
   - `REL4_*` — 관련 사례를 3건만 넣을 때(`<li>` 통째로)
   - 블록을 지운 뒤 `method-badge` 번호는 **1부터 다시** 매깁니다.
4. **소재지(`{{ADDRESS_LINE}}`·`{{OBJECT_STREET}}`)는 물건 종류에 따라 분기합니다.**
   - 집합건물(아파트·오피스텔·구분상가): `서울특별시 ○○구 ○○동 <지번>` — 지번은 쓰고 **동·층·호만 뺍니다**
   - 토지·일반건물(단독·다가구·근린생활시설): `서울특별시 ○○구 ○○동` — **지번을 쓰지 않습니다**
   - 도로명주소는 어느 경우에도 쓰지 않습니다. `{{H1_LINE1}}`·`{{REGION}}` 은 두 경우 모두 **동까지만**.
5. **기준시점은 `{{GIJUN_YEAR}}` 하나로 연도만** 넣습니다(`2025`). 템플릿의 `<time datetime="{{GIJUN_YEAR}}">`
   에 날짜를 넣지 마십시오. 본문 어디에도 기준시점의 월·일을 쓰지 않습니다.
   **`{{REPORT_DATE_ISO}}`(YYYY-MM-DD)·`{{REPORT_DATE_KR}}` 은 감정평가서 작성일**이며 월·일까지 씁니다.
   푸터의 `{{MODIFIED_DATE}}`·`{{MODIFIED_DATE_KR}}` 은 **사이트 갱신일**로, 작성일과 같은 값이 아닙니다.
6. **개요 그리드에 층수·호수 항목을 만들지 않습니다.** `{{INFO_LABEL_3~5}}` 에는 면적·구조·용도만 넣습니다.
   집합건물이면 `전유면적` · `공용면적/합계면적` · `대지권면적` 을, 토지건물이면 `토지면적/지목` · `건물 연면적` · `주구조/주용도` 를 씁니다.
7. **비교사례 표에 「동/층/호」 열을 만들지 않습니다.** 소재지 칸은 동(洞) 이름까지만,
   거래시점·기준시점 칸은 연도만, 나머지는 면적·거래가액·단가입니다.
8. **가치형성요인 표·요인치를 넣지 않습니다.** 산정단가는 `{{UNIT_PRICE_FORMULA}}` 한 줄로,
   `비교사례단가 × 사정보정 × 시점수정 = 산정단가` 까지만 보여줍니다.
   요인비교치가 1.000 이 아니면 **산식을 쓰지 말고 결과 산정단가만** 제시합니다.
   `{{CALC_GROUP1_STEPS}}` 의 calc-step 은 최대 4단계이며 요인비교 단계를 만들지 않습니다.
   시점수정 설명에는 **지수명과 최종 시점수정률만** 쓰고 적용 월을 쓰지 않습니다.
9. **소급감정을 시사하는 문구를 쓰지 않습니다.** "신고기한을 역산하여 … 일정을 관리합니다" 류 금지.

10. **분량을 압축합니다.** h2 8개 구조를 그대로 두고, 요약 단락은 2~3문장, 설명은 **이 사례에 관한 것만** 씁니다.
    일반론·정의 블록·법령 원문 장문 인용을 추가하지 마십시오. 완성본 텍스트가 **5,000자를 넘으면 줄입니다**
    (기준: `cases/dongjak-daebang-epyeonhansesang-2026.html` 약 4,660자).
11. **SEO 는 구조화 데이터로 싣습니다.** `{{JSONLD_KEYWORDS}}`·`{{META_KEYWORDS}}` 에 지역·물건·목적 조합을
    콤마로 넣고, `{{MENTION_1~4}}` 는 `상속재산 평가`·`시가인정액`·`상속세 신고`·`증여세 신고`·`취득세 시가인정액`·

`NNN` 은 3자리 0채움 순번입니다. 다음 번호는 **게시로그 + queue + review + published 전체**에서
가장 큰 번호 + 1 입니다.

```bash
python3 - <<'PY'
import os,re,io
A="/".join([os.environ["HOME"],"mnt","gaachi-website","automation"])
n=[0]
log=os.path.join(A,"state","published_log.tsv")
if os.path.exists(log):
    for ln in io.open(log,encoding="utf-8"):
        m=re.match(r'^\S+\t(\d+)_',ln)
        if m: n.append(int(m.group(1)))
for d in ("queue","review","published"):
    p=os.path.join(A,d)
    if os.path.isdir(p):
        for f in os.listdir(p):
            m=re.match(r'^(\d+)_',f)
            if m: n.append(int(m.group(1)))
print("다음 번호: %03d" % (max(n)+1))
PY
```

- 이미 존재하는 이름이면 **덮어쓰지 말고** 번호를 1 올려 새로 만듭니다.
- 승인 단계에서는 `automation/queue/` 에 직접 쓰지 않습니다(승인 게이트를 우회하게 됩니다).

# Step 7 — meta.tsv 작성

게시 스크립트(`publish_case_v1.py`)가 `index.html` 카드를 만들 때 읽는 사이드카입니다.
HTML 과 **같은 이름 + `.meta.tsv`** 로 같은 폴더에 저장합니다. 탭 구분, 한 줄에 `키<TAB>값`.

| 키 | 내용 |
|----|------|
| `num` | 카드 번호(2자리). 보통 `index.html` 의 마지막 `case-num` + 1 |
| `cat` | 카드 필터 카테고리 (`상속·증여` / `담보` / `보상` …) |
| `tag` | 카드 우상단 배지 (`상속 감정평가`) |
| `title_line1` | 카드 제목 1행 — 지역 |
| `title_line2` | 카드 제목 2행 — 물건 + `감정평가` |
| `purpose` | 카드 목적 설명 한 줄 |
| `sijae` | 소재지 (카드에는 **동 단위까지만**) |
| `gijun` | 기준시점 — **연도만** (`2025년`) |
| `method` | 대표 평가방법 |
| `value_text` | 최종 감정평가액 축약 (`15억 7,701만원`) |
| `seo_h2` | 카드 안 SEO 블록 `<h2>` 문구 |
| `seo_p` | SEO 문단. `\|\|` 로 나누면 `<p>` 여러 개가 됩니다 |

선택 키 `region` / `object` / `purpose_short` 는 커밋 메시지를 예쁘게 만드는 용도입니다(없어도 동작).

# Step 8 — 검증

```bash
cd "$HOME/mnt/gaachi-website" && \
```

검증기가 막는 항목:

- `<!DOCTYPE html>` · `<html lang="ko">` 존재

- **FAQPage 질문 == 본문 `<h3>` 질문** (다르면 양쪽 문자열을 나란히 출력합니다)
- `canonical` == `og:url` == `mainEntityOfPage.@id` == `https://gaachi.co.kr/cases/<slug>.html`
- 미치환 토큰 `{{ }}` 0건
- 숨김 키워드 스팬 0건
- 수수료·비용 금액 표현 0건 / 인명 패턴 0건 / `<\!--` 오타 0건
- `meta.tsv` 사이드카 존재 + 12개 키 전부 채움

**v3 추가 확인 — 검증기가 아직 막지 않으므로 Step 4-Z 스윕 결과로 직접 확인합니다.**

- 담당 감정평가사 성명 0건 / `"@type": "Person"` 0건 / `hasCredential` 0건
- `█` 0건 / `addr-mask` 0건 / 층·호 항목 0건 / 비교사례 동 번호 0건
- `datetime="YYYY-MM-DD"` 형태의 **기준시점** 0건 (감정평가서 작성일 `{{REPORT_DATE_ISO}}` 는 예외로 1~2건 정상)
- 가치형성요인 0건 / `역산` 0건 / 물건·비교사례 도로명주소 0건
- 텍스트 분량 5,000자 이하

**오류(✗)가 1건이라도 남으면 초안을 넘기지 않습니다.** 고쳐서 다시 돌리고, 0건이 될 때까지 반복합니다.
경고(△)는 사람이 확인할 항목이며, 내용상 문제가 없으면 그대로 두어도 됩니다.
고칠 수 없는 오류라면 초안 파일을 `automation/rejected/` 로 옮기고 사유를 남긴 뒤 사용자에게 보고합니다.

## 9-2. inventory 상태 갱신

해당 `seq` 행의 **10번 컬럼**을 `PENDING` → `DRAFTED` 로 바꿉니다.
다른 컬럼과 다른 행은 건드리지 않습니다. 파일 전체를 다시 쓰지 말고 아래처럼 해당 행만 치환합니다.

```bash
python3 - <<'PY'
import io
SEQ="1"                                  # 이번에 처리한 seq
p="/".join([__import__("os").environ["HOME"],"mnt","gaachi-website",
            "automation","sources","inventory_v1.tsv"])
lines=io.open(p,encoding="utf-8").read().split("\n")
hit=0
for i,ln in enumerate(lines):
    c=ln.split("\t")
    if len(c)>=12 and c[0]==SEQ and c[9]=="PENDING":
        c[9]="DRAFTED"; lines[i]="\t".join(c); hit+=1
assert hit==1, "치환 대상이 %d행입니다(1행이어야 함). 중단합니다." % hit
io.open(p,"w",encoding="utf-8",newline="").write("\n".join(lines))
print("inventory seq=%s -> DRAFTED" % SEQ)
PY
```

(반려되어 다시 만들어야 하는 경우에만 사용자 확인을 받고 `DRAFTED` → `PENDING` 으로 되돌립니다.
게시가 끝난 행은 사용자 또는 후속 작업이 `DONE` 으로 바꿉니다.)

# 금지사항 (하나라도 어기면 게시가 거부되거나 사고가 됩니다)

1. **담당 감정평가사·의뢰인·소유자·신청인 성명을 쓰지 않습니다.** JSON-LD `author` 는 Organization 입니다.
2. **본건의 동·층·호를 쓰지 않습니다.** 마스킹 기호(`█`)로도 쓰지 않고 **항목 자체를 삭제**합니다.
3. **기준시점·거래시점에 월·일을 쓰지 않습니다.** 연도만 씁니다(상속개시일 = 사망일이므로 개인정보).
4. **가치형성요인 표·요인치를 싣지 않습니다.** 산정단가 산식은 3항까지입니다.
5. **소급감정을 시사하는 문구를 쓰지 않습니다.** "신고기한을 역산하여 …" 류 금지.
6. **수수료·평가비용 금액을 절대 쓰지 않습니다.** `수수료`, `평가수수료`, `비용은 약` 은
   `automation/config/forbidden_phrases_v1.txt` 에 등록되어 있어 게시가 자동 거부됩니다.
7. **감정평가액이 공시가격보다 낮다는 취지로 쓰지 않습니다.** 절세 유인 서술 금지.
8. **상속·증여 평가기간을 정확히 씁니다.** 상속 = 상속개시일 **전 6개월 ~ 후 6개월**(12개월),
   증여 = 평가기준일 **전 6개월 ~ 후 3개월**(9개월). 가격산정기준일과 감정평가서 작성일이
   **모두** 이 기간 안에 들어와야 한다는 점까지 씁니다. (「상속세 및 증여세법 시행령」 제49조 제1항)
9. **추측한 숫자를 절대 쓰지 않습니다.** 확정하지 못한 값은 **해당 블록을 통째로 빼고**
   Step 9 로그 `note` 에 남깁니다. 필수 항목(최종 감정평가액·기준시점)이면 **그 사례는 만들지 않고 중단**합니다.
10. **검증하지 않은 법령 조문 번호를 인용하지 않습니다.** `templates/작성가이드_v3.md` §5 표 안에서만 씁니다.
11. **기존 파일을 삭제하거나 수정하지 않습니다.** `index.html`, `sitemap.xml`, `cases/`, `robots.txt`,
    `.gitignore`, `templates/` 의 기존 파일, `automation/publish_case_v1.py` 는 읽기 전용입니다.
12. **git 을 실행하지 않습니다.** 커밋·푸시는 게시 스크립트의 일입니다.
13. **`.json` 파일을 만들지 않습니다.**
14. **하루 1건을 넘겨 만들지 않습니다.**
15. **존재하지 않는 `/cases/*.html` 링크를 넣지 않습니다.**
16. **`<\!--` 오타를 쓰지 않습니다.** HTML 주석은 `<!--` 만 사용합니다.
17. **숨김 텍스트를 넣지 않습니다.** `font-size:1px`, `color:var(--bg)`, 인라인 `display:none`, 화면 밖 배치 전부 금지.
18. **도로명주소를 쓰지 않습니다**(물건·비교사례. 법인 본사 주소는 예외).
