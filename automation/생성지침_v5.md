## 0-C. 카테고리별 게시 건수 집계 (v5 신설 — Step 1 선정의 근거)

```bash

import io,os,re,glob
R=os.path.join(os.environ["HOME"],"mnt","gaachi-website")
idx=io.open(os.path.join(R,"index.html"),encoding="utf-8").read()
# 홈 카테고리 정본 = index.html 의 cat-btn 목록('전체' 제외)
CATS=[c for c in re.findall(r"filterCases\('([^']+)'",idx) if c!="전체"]
pub={c:0 for c in CATS}
for c in re.findall(r'data-cat="([^"]+)"',idx):            # 게시 완료(홈 카드)
    pub[c]=pub.get(c,0)+1
meta={c:0 for c in CATS}
for m in glob.glob(os.path.join(R,"automation","published","*.meta.tsv")):
    for ln in io.open(m,encoding="utf-8"):
        if ln.startswith("cat\t"):
```

## 1-D. **총괄 감정서는 물건(사이트)별로 각각 1개 사례** (2026-09-28 소유자 지시 — 결정 6)

소유자 지시 원문:
**"자산재평가 7건 중 5건이 총괄이면, 총괄로 1개를 만들지 말고, 각 싸이트(물건)별로 1개의 사례를 만들어줘."**

지금까지도 「총괄 합계가 아니라 본건 금액을 쓴다」(Step 2-A0)는 규칙은 있었지만,
**감정서 1건 = 사례 1건**을 전제로 나머지 물건은 버려 왔습니다. **앞으로는 물건 수만큼 사례를 만듭니다.**

### 절차

1. Step 2-A0 로 **총괄표에 물건이 몇 개인지(N)** 를 먼저 셉니다. **후보는 1건이 아니라 N건**입니다.
2. 물건 목록을 만듭니다 — 물건번호 · 소재지 · 용도 · 면적 · 금액을 **총괄표와 각 물건의 감정평가표에서** 적습니다.
3. **사례로 만들지 않는 물건을 먼저 뺍니다.**
   - **부동산이 아닌 물건**(회원권 · 기계기구만 · 차량 · 영업권 등) → **사례로 만들지 않습니다.**
   - 유형 C-1(임대사례비교법·보정항만)에 해당하는 물건 → 게시 대상 제외(Step 2-D).
4. **물건마다 따로 판정합니다.**
   - **특정 가능성**(작성가이드 v5 §4-4 의 세 유형) — **한 물건이 보류여도 다른 물건은 게시할 수 있습니다.**
   - **`MASK_LEVEL`** (Step 1-C) — 물건마다 `exact`/`range` 가 다를 수 있습니다.
   - **목적 분기**(Step 1-B) — 같은 감정서면 보통 같지만, 목적란 인쇄 문구를 물건별로 확인합니다.
5. **하루 생성 건수 규칙(Step 0-A)은 그대로입니다.** 버퍼 0~2 → 최대 3건 / 3~4 → 1건 / 5 이상 → 중단.
   **N건을 한 번에 다 만들지 마십시오.** 오늘 만들 수 있는 수만큼만 만들고 나머지는 다음 실행으로 넘깁니다.
6. **남은 물건의 표시 방법** — `inventory_v1.tsv` 의 그 seq 행에서
   - `status` 는 **`PENDING` 그대로 둡니다**(물건이 남아 있으므로 `DRAFTED` 로 바꾸지 않습니다).
   - `notes` 끝에 **`총괄 N물건 중 x번 DRAFTED, 나머지 대기`** 를 덧붙입니다.
     이미 같은 표시가 있으면 숫자만 갱신합니다(예: `총괄 5물건 중 1,3번 DRAFTED, 나머지 대기`).
   - **모든 물건을 다 만들었을 때 비로소** `status` 를 `DRAFTED` 로 바꾸고 `notes` 를 `총괄 N물건 전부 DRAFTED` 로 바꿉니다.
   - (inventory 수정은 **Step 9-2 에서만** 합니다. Step 1 에서는 읽기만 하십시오.)

### 각 사례를 만들 때 지킬 것

- **각 사례는 그 물건의 감정평가표 · 명세표 · 시산가액표만 근거**로 합니다.
  소재지 · 면적 · 금액 · 용도가 물건마다 다릅니다. **총괄 합계 금액은 어느 사례에도 쓰지 않습니다.**

- **같은 감정서에서 나온 사례끼리 `REL1~REL4` 로 서로 링크하지 않습니다.**
  묶이면 「같은 의뢰인의 여러 물건」이 드러나 의뢰인이 특정됩니다. 관련사례는 **다른 감정서의 사례**로 채웁니다.
- Step 9 로그 `note` 에 **`총괄 N물건 중 x번`** 과 그 물건의 소재지·금액을 남깁니다.

# Step 1-C — `MASK_LEVEL` 판정 (v5 신설, 결정 3)

`MASK_LEVEL` 은 `exact`(기본) 또는 `range`(구간 처리) 둘 중 하나입니다.
`.meta.tsv` 에 `mask_level` 키로 적고, 검증기 v2 가 이 값을 읽어 검사 강도를 바꿉니다.

## 판정 기준

| 조건 | `MASK_LEVEL` |
|------|--------------|
| 개인 소유·개인 의뢰 (상속·증여, seq 67 논현동 같은 개인 소유 임대료) | `exact` |
| 법원 촉탁 경매로 소유자가 개인 | `exact` |
| 법인 소유이지만 물건이 **흔한 유형**이고 규모·위치로 특정되지 않음 (예: 가산동 지식산업센터 1개호) | `exact` |
| **법인 소유이면서 특정 가능성이 높음** — 신탁재산, 유동화 공매, 단일 공장·단일 사옥, 대형·희소 물건 | **`range`** |
| 업종·설비·임차인이 드러나면 회사가 좁혀지는 건 | **`range`** |
| 구간 처리로도 가려지지 않는 고유 사실(지점명·화재·역명 등)이 산식 근거인 건 | **게시 보류** (Step 1-B 제외 규칙 3) |

결정서가 이미 정해 놓은 값은 **Step 1-A 표를 그대로 따릅니다**(55·58/63·67·66·51 = `exact`, 41/46/52·42·43·57/59 = `range`).
표에 없는 건은 위 기준으로 판정하고, **판단이 갈리면 `range` 쪽으로** 기울이십시오.

## `MASK_LEVEL=range` 일 때의 표기 규칙

| 항목 | 처리 |
|------|------|
| 면적 | 유효숫자 2자리 구간. `18,012.37㎡` → `약 1.8만㎡`, `5,123.7㎡` → `약 5,100㎡` |
| 감정평가액·임대료 | 억 단위 절사 + `대`. `4,739,811,458원` → `47억원대`, `8,083,397,520원` → `80억원대` |
| 필지 수·동 수 | `다수 필지` · `공장 여러 동`. **정확한 개수 미표기** |
| 결정단가·산출금액 | **표시하지 않는다.** 구간 면적과 곱이 맞지 않아 오류로 읽힌다 |
| JSON-LD `about.price` · `VALUE_NUMERIC` | **속성째 삭제.** 구간값을 숫자 필드에 넣지 않는다 |
| 비교사례 표 | 면적·금액을 같은 구간 규칙으로. **단가 열 삭제** |
| 업종·설비 품목·임차인 | 쓰지 않는다. `제조업 공장`·`기계기구 일괄` 수준 |
| `value_text`(meta) | `47억원대` 처럼 구간 표기 |

> `range` 건은 **규칙 B의 산식 자체를 싣지 않습니다.** `CALC_*` 블록을 통째로 빼고
> 「적용 감정평가방법과 근거 조문 + 결과 구간」만 서술하십시오.

## 2-A0. ⚠⚠ 총괄표 재확인 (v5에서 **강한 경고**로 승격) ⚠⚠

> **조사 결과 자산재평가 7건 중 5건의 `inventory.value_krw` 가 총괄 합계였습니다.**
> 상속·증여 건에서도 002·003·004·007 이 같은 함정에 걸렸습니다.
> **이 절차를 건너뛰면 잘못된 금액이 게시됩니다. 예외 없이 수행하십시오.**

총괄표가 붙은 감정서의 신호:
1. 원본 **파일명에 `총괄`** 이 들어 있다
2. 같은 `file_id` 의 **분번(`-01` · `-02` · `-A` 등)** 이 inventory 나 PDF 폴더에 있다
3. 감정평가표 앞에 **「감정평가액 총괄표」** 장이 있다
4. `value_krw` 가 물건 규모에 비해 부자연스럽게 크다

```bash
# 분번 존재 여부 확인 (file_id 를 넣고 실행)
FID="HQ20255-10007"
awk -F'\t' -v f="$FID" '$2 ~ "^"f {print $1"\t"$2"\t"$4" "$5"\t"$8}' \
  "$HOME/mnt/gaachi-website/automation/sources/inventory_v1.tsv"
ls -1 "$HOME/mnt/신규홈페이지/감정서 샘플/" | grep -i "${FID%%-*}" | head -20
```

**규칙**: 위 신호가 하나라도 있으면
→ **합계를 쓰지 말고, 해당 분번의 감정평가표에 인쇄된 금액을 씁니다.**
→ 총괄표에서 물건별 금액을 **전부 적어** Step 9 로그 `note` 에 남깁니다(어느 금액이 어느 물건인지).
→ 본건 금액과 `inventory.value_krw` 가 다르면 **PDF가 우선**이며 `[inventory 정정]` 으로 로그에 남깁니다.

> **2026-09-28 결정 6** — 총괄표에 물건이 **N개면 사례도 N건**입니다.
> 물건 하나만 고르고 나머지를 버리지 마십시오. 절차는 **Step 1-D** 에 있습니다.
> 여기서 적어 둔 **물건별 금액·소재지 목록이 곧 Step 1-D 의 후보 목록**입니다.

**총괄표가 단일 물건이어서 합계 = 본건인 경우에도** "총괄 확인 결과 단일 물건, 합계 아님"을 로그에 남기십시오.
(확인했다는 기록이 없으면 확인하지 않은 것으로 봅니다.)

## 4-C. 기준시점 표기 분기 (v5 신설, 결정 2)

| 목적 분기 | 기준시점 표기 |

- 재무보고 건은 기준시점이 **결산일**이라 작성일과 최대 1년 가까이 벌어집니다.

`NNN` 은 **게시로그 + queue + review + published 전체**에서 가장 큰 번호 + 1 (3자리 0채움).

```bash
python3 - <<'PY'
import os,re,io
A=os.path.join(os.environ["HOME"],"mnt","gaachi-website","automation")
n=[0]
log=os.path.join(A,"state","published_log.tsv")
if os.path.exists(log):
    for ln in io.open(log,encoding="utf-8"):
        m=re.match(r'^\S+\t(\d+)_',ln)
        if m: n.append(int(m.group(1)))
for d in ("queue","review","published"):
    p=os.path.join(A,d)
    if os.path.isdir(p):
        for f in os.listdir(p):
            m=re.match(r'^(\d+)_',f)
            if m: n.append(int(m.group(1)))
print("다음 번호: %03d" % (max(n)+1))
PY
```

- 이미 있는 이름이면 **덮어쓰지 말고** 번호를 올립니다.

## 6-A. 총괄 감정서에서 나온 물건별 사례의 번호·slug (2026-09-28 결정 6 — Step 1-D 와 짝)

- **번호(NNN)** — 물건마다 **각각 새 번호**를 받습니다. 같은 번호에 `-1`·`-2` 를 붙이지 마십시오.

- **slug** — 물건마다 다릅니다. **그 물건의 소재지(동 단위)와 물건종류**로 만듭니다.
  같은 감정서라고 해서 slug 에 공통 접두어·일련번호를 붙이지 마십시오
  (`...-1` · `...-2` 는 **같은 의뢰인의 묶음이라는 신호**가 되어 특정 위험을 만듭니다).

  - ❌ `haman-gimhae-gongjang-jaepyeongga-2025-1` / `...-2`
- **`meta.tsv`** — 물건마다 별도입니다. `num`·`sijae`·`value_text`·`gijun`·`method` 를 **그 물건의 값**으로 채웁니다.

## 7-C. v5 신설 3키 (검증기 v2 가 읽습니다)

| 키 | 값 | 기본값 | 용도 |
|----|-----|--------|------|
| `purpose_branch` | `상속증여` / `재무보고` / `임대료` / `경매공매` / `구조화금융` / `기타` | `cat` 에서 추정 | 목적별 법령 오염 검사 |
| `mask_level` | `exact` / `range` | `exact` | 구간 처리 검사 |
| `owner_type` | `개인` / `법인` / `부동산신탁회사` / `유동화전문회사` / `법원` | `개인` | 법인 마스킹 검사 |

- **`cat` 이 `부동산컨설팅` 인 건은 `purpose_branch` 를 반드시 명시하십시오.** 임대료와 매수 검토가 섞여 있어
  `cat` 만으로는 분기를 정할 수 없습니다. 없으면 검증기가 경고를 냅니다.

## 9-2. inventory 상태 갱신
해당 `seq` 행의 **10번 컬럼**을 `PENDING` → `DRAFTED` 로.

> ⚠ **총괄 감정서(물건 N개)는 다릅니다** (Step 1-D · 결정 6).
> **물건을 전부 만들기 전에는 `status` 를 `DRAFTED` 로 바꾸지 마십시오.**
> - 일부만 만든 경우 → `status` 는 **`PENDING` 유지**. `notes`(12번 컬럼) 끝에
>   **`총괄 N물건 중 x번 DRAFTED, 나머지 대기`** 를 덧붙입니다(같은 표시가 있으면 숫자만 갱신).
> - 물건을 **전부** 만든 뒤에야 `status` → `DRAFTED`, `notes` → `총괄 N물건 전부 DRAFTED`.
> - 단일 물건 감정서는 종전대로 바로 `DRAFTED` 입니다.

```bash
python3 - <<'PY'
import io,os
SEQS={"55"}          # ← 이번에 처리한 seq 들
p=os.path.join(os.environ["HOME"],"mnt","gaachi-website","automation","sources","inventory_v1.tsv")
lines=io.open(p,encoding="utf-8").read().split("\n")
hit=0
for i,ln in enumerate(lines):
    c=ln.split("\t")
    if len(c)>=12 and c[0] in SEQS and c[9]=="PENDING":
        c[9]="DRAFTED"; lines[i]="\t".join(c); hit+=1
assert hit==len(SEQS), "치환 %d행(기대 %d). 중단." % (hit,len(SEQS))
io.open(p,"w",encoding="utf-8",newline="").write("\n".join(lines))
print("inventory -> DRAFTED:", hit)
PY
```

> **같은 의뢰인 택1로 버린 건**(예: 57을 골랐으면 59)은 `status` 를 건드리지 말고
> 로그 `note` 에만 "영구 제외 — 같은 의뢰인 seq 57 선정" 으로 남깁니다.
