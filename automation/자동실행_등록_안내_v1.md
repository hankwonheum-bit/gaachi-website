# 사례 자동 게시 — 자동 실행 등록 안내 v1

매일 사례 1건을 홈페이지에 자동으로 올리려면, 이 PC 가 스스로
`automation/publish_case_v1.py` 를 실행하도록 등록해 두어야 합니다.

등록 방법은 두 가지입니다. **방법 A 를 먼저 시도하고, 안 되면 방법 B** 를 쓰세요.

| | 방법 A — 작업 스케줄러 | 방법 B — 시작프로그램 |
|---|---|---|
| 관리자 권한 | 필요함 (UAC) | **필요 없음** |
| 실행 시점 | 로그온 3분 후 + **매일 09:00** | 로그온 후 약 10~20초 |
| PC 를 며칠 계속 켜 둘 때 | 매일 실행됨 | **실행 안 됨** |
| 등록 위치 | 작업 스케줄러 라이브러리 | `shell:startup` 폴더 |

---

## 방법 A (권장) — 작업 스케줄러

관리자 권한을 쓸 수 있다면 이 방법이 낫습니다. 정해진 시각에 실행되기 때문에
컴퓨터를 껐다 켜지 않아도 매일 게시됩니다.

### 등록하기

1. 파일 탐색기에서 `C:\Users\user\Documents\GitHub\gaachi-website\automation` 폴더를 엽니다.
2. **`관리자로_등록하기_v1.bat`** 파일을 더블클릭합니다.
3. UAC(사용자 계정 컨트롤) 창이 뜨면 **[예]** 를 누릅니다.
4. 검은 창이 하나 더 열리고 한국어로 `등록 완료!` 가 보이면 끝입니다.
   창은 `아무 키나 누르십시오` 가 나올 때까지 기다렸다가 닫으면 됩니다.

> `관리자로_등록하기_v1.bat` 은 스스로 관리자 권한을 요청한 뒤
> `register_task_v2.ps1` 을 실행합니다. 직접 PowerShell 을 관리자 권한으로 열어
> `powershell -ExecutionPolicy Bypass -File .\automation\register_task_v2.ps1` 을
> 실행해도 결과는 같습니다.
>
> 오류 메시지를 더 친절하게 보고 싶다면 `register_task_v3.ps1` 을 쓰셔도 됩니다.
> 등록하는 내용은 v2 와 똑같고, 권한이 없을 때 무엇을 해야 하는지 알려 줍니다.

### 확인하기

- `Win + R` → `taskschd.msc` → 확인
- 왼쪽에서 **작업 스케줄러 라이브러리** 를 클릭
- 목록에 **`가치앤같이_사례자동게시`** 가 있으면 등록된 것입니다.
- 지금 바로 시험해 보려면 그 작업을 오른쪽 클릭 → **실행**

### 해제하기

```
powershell -ExecutionPolicy Bypass -File .\automation\register_task_v2.ps1 -Remove
```

(관리자 권한이 필요합니다. `register_task_v3.ps1 -Remove` 도 같은 일을 합니다.)

## 방법 B — 시작프로그램 (관리자 권한이 없거나 회사 정책으로 막힌 경우)

`Register-ScheduledTask : Access is denied` 또는 `0x80070005` 오류가 나거나,
UAC 창에서 [예] 를 누를 수 없다면 이 방법을 쓰세요.
사용자 본인의 시작프로그램 폴더에 바로 가기를 만들 뿐이라 관리자 권한이 전혀 필요 없습니다.

### 등록하기

PowerShell 을 열고(관리자 권한 아니어도 됩니다) 저장소 폴더에서 아래 한 줄을 붙여 넣습니다.

```
cd C:\Users\user\Documents\GitHub\gaachi-website
powershell -ExecutionPolicy Bypass -File .\automation\register_startup_v1.ps1
```

`등록 완료!` 와 함께 시작프로그램 폴더 경로, 바로 가기 대상이 출력되면 끝입니다.

### 확인하기

- `Win + R` → `shell:startup` → 확인
- 열린 폴더에 **`가치앤같이_사례자동게시`** 바로 가기가 있으면 등록된 것입니다.
- 바로 가기를 더블클릭하면 지금 바로 한 번 실행해 볼 수 있습니다(창은 뜨지 않습니다).

### 해제하기

```
powershell -ExecutionPolicy Bypass -File .\automation\register_startup_v1.ps1 -Remove
```

또는 `shell:startup` 폴더에서 그 바로 가기를 그냥 삭제해도 됩니다.

### 방법 B 의 한계 (꼭 읽어 주세요)

시작프로그램은 **로그온할 때만** 실행됩니다. 정해진 시각에 실행되는 것이 아닙니다.
그래서 컴퓨터를 끄지 않고 며칠 계속 켜 두면, 그 기간 동안 한 번도 게시되지 않습니다.
매일 퇴근할 때 PC 를 끄고 아침에 켜는 식으로 쓰신다면 방법 B 로도 충분합니다.
그렇지 않다면 가능한 한 방법 A 로 등록하시는 편이 좋습니다.

## 둘 다 등록해도 괜찮습니다

방법 A 와 방법 B 를 모두 등록해 두어도 하루에 2건이 올라가지 않습니다.

`publish_case_v1.py` 는 실행되자마자 **오늘 이미 게시했는지** 먼저 확인하고,
이미 게시했으면 `오늘은 이미 게시됨` 만 로그에 남기고 아무 것도 하지 않습니다(멱등 처리).
게시 기록은 `automation/logs/publish-YYYYMMDD.log` 에 남습니다.

그러므로 방법 A 가 될지 안 될지 모르겠다면, **방법 B 를 먼저 등록해 두고**
나중에 관리자 권한이 생겼을 때 방법 A 를 추가해도 안전합니다.
(정리하고 싶으면 그때 방법 B 를 `-Remove` 로 해제하면 됩니다.)

일부러 하루에 1건 더 올리고 싶을 때만 아래처럼 `--force` 를 씁니다.

```
py -3 automation\publish_case_v1.py --force
```

## 잘 되고 있는지 보는 법

| 무엇을 볼까 | 어디 |
|---|---|
| 게시 기록 (날짜/사례/URL/결과) | `automation\logs\publish-YYYYMMDD.log` |
| 마지막 실행의 원본 출력 | `automation\logs\run_last.log` |
| 설치 상태 전체 점검 | `automation\점검_v2.bat` 더블클릭 |
| 실제 게시 없이 예행 연습 | `py -3 automation\publish_case_v1.py --dry-run` |

## 관련 파일

| 파일 | 하는 일 |
|---|---|
| `관리자로_등록하기_v1.bat` | 방법 A. 관리자 권한을 요청하고 `register_task_v2.ps1` 실행 |
| `register_task_v2.ps1` | 방법 A 의 실제 등록 스크립트 (관리자 권한 필요) |
| `register_task_v3.ps1` | v2 와 같은 등록 + 권한 오류를 한국어로 안내 |
| `register_startup_v1.ps1` | 방법 B. 시작프로그램에 바로 가기 등록 (관리자 권한 불필요) |
| `run_hidden_v2.vbs` | 창 없이 `run_daily_v2.bat` 실행 |
| `run_daily_v2.bat` | Python 을 찾아 `publish_case_v1.py` 실행 |
| `publish_case_v1.py` | 실제 게시 (하루 1건, 멱등) |
