# 감정평가 사례 페이지 작성가이드 v2 (GEO 대응판)

> 대상: `templates/case_template_v2.html` 로 새 사례 페이지를 만드는 사람 또는 자동 생성기
> 작성: 2026-09-15 · 적용 법인: ㈜감정평가법인 가치앤같이

---

## 0. 이 문서가 존재하는 이유

기존 v1 사례 페이지(`cases/*.html`)는 사람이 읽기에는 문제가 없지만, **기계가 읽기에는 구조가 없습니다.**
GEO(Generative Engine Optimization) 감사 결과 아래 5가지 결함이 확인되었습니다.

| # | v1 결함 | 영향 |
|---|---------|------|
| 1 | `<h2>`·`<h3>` 태그가 **0개**. 섹션 제목이 전부 `<div class="section-title">` | LLM·검색엔진이 문서 구조를 인식하지 못함 |
| 2 | 상단에 **직답 단락 없음**. 결론이 그래픽 박스(`case-value-num`) 안에만 있음 | 인용할 텍스트 청크가 없음 |
| 3 | **법령 출처 인용 없음**. 조문 번호가 본문에 흩어져 있고 출처 섹션이 없음 | 근거 부족으로 인용 순위 하락 |
| 4 | **엔티티 희석**. "본 법인", "당사" 사용 | 청크 단위 검색에서 법인이 특정되지 않음 |
| 5 | FAQ 가 **JSON-LD 에만** 존재. 본문에는 `<div>` 뿐 | Google 은 2026-05-07 FAQ 리치 결과를 전면 폐지했고, LLM 은 JSON-LD 를 파싱이 아니라 토큰화한다 |

v2 는 이 5가지를 전부 고치되, **화면에 보이는 디자인은 v1 과 동일하게** 유지합니다.

## 1. 근거 데이터 — 무엇을 해야 하고 무엇을 하면 안 되는가

### 1-1. GEO 개입 효과 (arXiv:2311.09735, KDD 2024)
기준선(baseline) 가시성 **19.3%** 대비 각 개입의 효과:

| 개입 | 결과 | 기준선 대비 | v2 적용 |
|------|------|------------|---------|
| **Quotation Addition** (인용문 추가) | **27.2%** | **+7.9%p** | 법령 조문을 큰따옴표로 **직접 인용** (`근거 법령 및 출처` 섹션) |
| **Statistics Addition** (통계 추가) | **25.2%** | **+5.9%p** | 면적·단가·시점수정률·기준시점을 **본문에 숫자로** 명시 |
| **Fluency Optimization** (문장 유창성) | 24.7% | +5.4%p | 표·박스가 아니라 **완결된 문장**으로 서술 |
| **Cite Sources** (출처 표기) | 24.6% | +5.3%p | 국토교통부 실거래가·한국부동산원·표준지공시지가 **출처 명시** |
| **Keyword Stuffing** (키워드 반복) | **17.7%** | **−1.6%p (역효과)** | **금지.** 숨김 키워드 스팬 전면 제거 |

### 1-2. AI 인용 상관계수 (arXiv:2509.10762, 1,100 URL 연구)

| 요인 | 상관계수 r |
|------|-----------|
| 메타데이터 / 최신성 | 0.68 |
| **시맨틱 HTML** | **0.65** |
| 구조화 데이터(JSON-LD) | 0.63 |

→ **시맨틱 HTML(`h1`/`h2`/`h3`)이 JSON-LD보다 상관이 높습니다.** JSON-LD 는 보조이고, 본체는 본문 태그입니다.
→ `article:modified_time` 과 `<time datetime>` 을 **실제로 갱신**하는 것이 단일 항목으로 가장 효과가 큽니다.

### 1-3. 여기서 나오는 3가지 작성 원칙

1. **통계를 본문에 숫자로 쓴다.** "약 8백만원대" ✗ → "8,350,000원/㎡" ✓. 면적·단가·시점수정률·개별요인치·기준시점은 반드시 숫자.
2. **법령 조문을 큰따옴표로 인용한다.** "제14조에 따라" ✗ → 「감정평가에 관한 규칙」 제14조 “…공시지가기준법을 적용해야 한다” ✓
3. **법인 정식명칭을 섹션마다 1회 이상, 완전한 형태로 반복한다.** 단, **키워드 스터핑은 금지**.
   - ✓ `㈜감정평가법인 가치앤같이` (또는 `㈜감정평가법인 가치앤같이(서울특별시 서초구 강남대로 86, 5층 501호)`)
   - ✗ `본 법인`, `당사`, `저희 법인`, `가치앤같이는` 단독
   - ✗ 의미 없이 같은 문장에 2회 이상 반복하거나, 숨김 스팬에 키워드를 나열

## 2. 마스킹 규칙 (CLAUDE.md §1 준수 — 예외 없음)

| 항목 | 처리 방법 | 마크업 |
|------|-----------|--------|
| 의뢰인·소유자·신청인 성명 | **완전 삭제** | — |
| 본건 층수 | 마스킹 | `제<span class="addr-mask">█</span>층` |
| 본건 호수 | 마스킹 | `<span class="addr-mask">███</span>호` |
| 지번 | 마스킹 | `성내동 <span class="addr-mask">███</span>` |
| 보고서 번호 | **표시 안 함** | — |
| 감정평가전례 기준시점 | **연도만** 표시 | `2025년` (○) / `2025.03.14.` (✗) |
| 감정평가전례 목적 | `—` 처리 | `<td>—</td>` |
| 비교사례 층수 | **삭제** (동/호만 표시) | `104동 <span class="addr-mask">███</span>` |
| 주소 표기 | **동 단위까지** | `서울 강동구 성내동` (○) / `성내동 123-4` (✗) |

담당 **감정평가사 성명**은 마스킹 대상이 아닙니다(전문가 표기). `{{APPRAISER_NAME}}` 에 소속 감정평가사 성명을 넣고,
JSON-LD `author` 의 `Person` + `hasCredential`(감정평가사, `recognizedBy` 한국감정평가사협회)로 E-E-A-T 신호를 만듭니다.

`.addr-mask` CSS 는 v2 템플릿에서 **전역 선언**되어 있습니다. v1 의 `gangdong-seongnae-2025.html` 은
`.comp-table .addr-mask` 만 있어 `section-summary` 안의 마스킹이 렌더링되지 않는 버그가 있었습니다. v2 에서 수정되었습니다.

## 3. 내용 금지 사항 (게시 차단)

### 3-1. 수수료·비용 금액을 **절대 쓰지 않는다**
`automation/config/forbidden_phrases_v1.txt` 에 `수수료`, `평가수수료`, `비용은 약` 이 등록되어 있어
해당 문자열이 포함되면 **게시가 거부**됩니다.

- ✗ "감정평가 수수료는 약 200만원입니다"
- ✗ "예상 감정평가액 · 수수료 무료 사전 검토를 제공합니다" ← v1 CTA 문구. **v2 에서 제거됨**
- ✓ "사전 검토 후 일정과 절차를 안내해 드립니다"

### 3-2. 감정평가액이 공시가격보다 낮다는 취지로 쓰지 않는다
- ✗ "감정평가를 받으면 공시가격보다 낮게 평가되어 세금이 줄어듭니다"
- ✗ "공시가격 대비 절감 효과"
- ✓ "「상속세 및 증여세법」 제60조는 시가를 원칙으로 하며, 감정가액은 시가로 인정되는 가액에 포함됩니다."
- ✓ 사실로서의 금액 비교는 가능하나, **절세를 유인하는 서술은 금지**합니다.

### 3-3. 상속·증여 기간 기준을 정확히 쓴다
「상속세 및 증여세법 시행령」 제49조 제1항:

> "상속개시일 또는 증여일 전후 6개월(증여재산의 경우에는 평가기준일 전 6개월부터 평가기준일 후 3개월까지로 한다)"

| 구분 | 평가기간 | 총 기간 |
|------|----------|---------|
| **상속** | 상속개시일 **전 6개월 ~ 후 6개월** | 12개월 |
| **증여** | 증여일(평가기준일) **전 6개월 ~ 후 3개월** | 9개월 |

- ✗ "상속·증여 모두 전후 6개월"
- ✗ "증여는 증여일로부터 6개월 이내"
- ✓ 가격산정기준일과 감정평가서 작성일이 **모두** 이 기간 안에 들어와야 한다는 점까지 명시

### 3-4. 기타
- `<\!--` 오타 금지 (`<!--` 만 사용). 게시 스크립트가 차단합니다.
- 존재하지 않는 `/cases/*.html` 링크 금지 (관련 사례 블록).
- **검증하지 않은 조문 번호를 쓰지 않습니다.** 아래 §4 목록 외의 조문을 인용하려면 국가법령정보센터(law.go.kr) 현행 조문을 먼저 확인하십시오.

## 5. v2 문서 구조 (이 순서를 바꾸지 않습니다)

```
<h1>  [지역] [물건종류] [평가목적] 감정평가 사례 (기준시점 YYYY년 M월)
      └ <p class="lead-answer">  ★직답 단락 — 최종액·기준시점·평가방법·법인 정식명칭+소재지
<h2>  [정의] ○○ 감정평가란 무엇인가요?
<h2>  [지역] [물건]은(는) 어떤 물건인가요?
<h2>  [지역] [물건]의 감정평가액은 얼마인가요?          ← 핵심 질문
<h2>  이 사례는 어떤 방법으로 평가했나요?
        <h3> 토지 — 공시지가기준법
        <h3> 토지 — 거래사례비교법 (결정단가 도출)
        <h3> 건물 — 원가법 (잔가법)
        <h3> 수익환원법 — 미적용
<h2>  어떤 비교사례를 근거로 삼았나요?
        <h3> 감정평가전례 N건 …
        <h3> 거래사례 N건 …
<h2>  감정평가액은 어떻게 계산되었나요?
        <h3> LAND — 거래사례비교법
        <h3> BUILDING — 원가법 (잔가법)
<h2>  상속·증여 감정평가는 언제까지 받아야 하나요?      ← 시행령 제49조
<h2>  이 물건에 적용되는 공법상 제한은 무엇인가요?
<h2>  자주 묻는 질문
        <h3> Q1 …  ← FAQPage JSON-LD 질문과 글자 단위 완전 일치
        <h3> Q2 …
        <h3> Q3 …
        <h3> Q4 …
<h2>  근거 법령 및 출처
<h2>  ㈜감정평가법인 가치앤같이는 어떤 법인인가요?
<h2>  함께 보면 좋은 감정평가 사례                       ← 허브 1 + 형제 3~5
CTA → /#contact
```

**핵심 규칙**
- `h2` 는 **질문형**으로 씁니다. LLM 의 청크 검색은 "질문↔단락" 쌍에 강하게 반응합니다.
- 화면상 골드색 작은 영문 라벨(`.section-title`)은 **장식용 `<div>` 로 유지**합니다. 11px·자간 4px·대문자 스타일에 긴 한국어 질문을 넣으면 가독성이 무너지기 때문입니다. 실제 표제는 바로 아래 `<h2 class="section-h2">` 이며, 기존 `.case-cta-title` 과 동일한 타이포(Noto Serif KR 18px/700)를 씁니다.
- 각 섹션은 **단독으로 읽어도 완결**되어야 합니다(청크 단위 검색). 섹션마다 지역명·물건명·법인 정식명칭을 최소 1회씩 다시 씁니다.
- FAQ 는 `<h3 class="faq-q-heading"><button class="faq-q">…</button></h3>` 구조입니다.
  `<h3>` 가 바깥, `<button>` 이 안쪽이라 **시맨틱 태그와 버튼 접근성을 동시에** 만족합니다.
  (`<button>` 안에 `<h3>` 를 넣으면 HTML 스펙 위반입니다 — 버튼의 내용 모델은 phrasing content 입니다.)

## 6. Worked example — 실제 데이터로 보는 v1 vs v2

아래는 `cases/gangdong-seongnae-2025.html` (강동구 성내동 근린생활시설, 상속, 기준시점 2025-11-07,
최종 1,577,010,440원, 토지 거래사례비교법 8,350,000원/㎡, 건물 원가법)의 실제 데이터입니다.

### 6-1. 페이지 상단 (헤더)

**v1 — 현재**
```html
<div class="case-header">
  <div class="case-tag">상속 감정평가</div>
  <h1>서울 강동구 성내동<br>근린생활시설 감정평가</h1>
  <div class="case-header-sub">서울특별시 강동구 성내동 근린생활시설 ·
    기준시점 <time datetime="2025-11-07">2025년 11월 7일</time> · 상속세 신고 목적 감정평가</div>
  <div class="case-byline">작성: ㈜감정평가법인 가치앤같이 ·
    <time datetime="2026-04-23">2026년 4월 23일</time></div>
  <div class="case-value-box">
    <div class="case-value-label">최종 감정평가액</div>
    <div class="case-value-num">15억 7,701만원</div>
    <div class="case-value-won">₩ 1,577,010,440</div>
  </div>
</div>
```
문제: 결론이 `<div class="case-value-num">15억 7,701만원</div>` 이라는 **숫자 조각**으로만 존재.
LLM 이 인용하려면 "무엇이" 15억 7,701만원인지 여러 요소를 조합해야 하는데, 청크가 잘리면 조합이 불가능합니다.

**v2 — 직답 단락 추가 + h1 에 기준시점 명시**
```html
<div class="case-header">
  <div class="case-tag">상속 감정평가</div>
  <h1>서울 강동구 성내동<br>근린생활시설 상속 감정평가 사례 (기준시점 2025년 11월)</h1>

  <p class="lead-answer">㈜감정평가법인 가치앤같이(서울특별시 서초구 강남대로 86, 5층 501호)가
    수행한 서울특별시 강동구 성내동 근린생활시설의 <strong>최종 감정평가액은 1,577,010,440원</strong>이며,
    기준시점은 <time datetime="2025-11-07">2025년 11월 7일</time>입니다.
    토지 177㎡는 거래사례비교법으로 결정단가 8,350,000원/㎡을 적용해 1,477,950,000원,
    건물 연면적 314.68㎡는 원가법(잔가법)으로 99,060,440원을 산정하여 합산하였습니다.
    상속세 신고 및 관할 세무서 제출 목적의 감정평가로,
    「상속세 및 증여세법」 제60조의 시가를 기준가치로 적용하였습니다.</p>

  <div class="case-header-sub">…</div>
  <div class="case-byline">작성: ㈜감정평가법인 가치앤같이 · 담당 감정평가사 김지광 ·
    최종 업데이트 <time datetime="2026-09-15">2026년 9월 15일</time></div>
  <div class="case-value-box">…</div>   <!-- 그래픽 박스는 그대로 유지 -->
</div>
```
개선 근거: 이 한 단락이 **Statistics Addition(+5.9%p)** 과 **Fluency(+5.4%p)** 를 동시에 충족하며,
이 단락만 잘려 나가도 결론·기준시점·평가방법·평가주체가 전부 들어 있습니다. `.case-value-box` 는 그대로 두어 화면은 변하지 않습니다.

### 6-2. 감정평가 방법론 섹션

**v1 — 현재** (`<h2>`·`<h3>` 0개)
```html
<div class="case-section" id="method">
  <div class="section-title">감정평가 방법론 — 토지 · 건물 분리 평가</div>
  <div class="method-list">
    <div class="method-item selected">
      <div class="method-badge">1</div>
      <div>
        <div class="method-name">토지 — 거래사례비교법</div>
        <div class="method-reason">「감정평가에 관한 규칙」 제14조 근거. 인근 유사 토지 거래사례
          (복합부동산 포함) 수집 후 건물가액을 공제하여 순토지단가를 추출하고 …</div>
      </div>
    </div>
    …
  </div>
</div>
```
문제 3가지:
1. 섹션 제목이 `<div>` → 문서 구조 없음
2. 소제목이 `<div class="method-name">` → 하위 구조 없음
3. **"제14조 근거"라고만 하고 조문을 인용하지 않음** → Quotation Addition(+7.9%p) 미달.
   게다가 제14조의 실제 내용은 **공시지가기준법**인데 v1 은 이를 "거래사례비교법"의 근거로 표기해 **조문과 내용이 어긋납니다.**

**v2**
```html
<div class="case-section" id="method">
  <div class="section-title">Methodology</div>            <!-- 장식용 라벨, 화면 동일 -->
  <h2 class="section-h2">이 사례는 어떤 방법으로 평가했나요?</h2>
  <p class="section-summary">토지와 건물이 각각 등기된 복합부동산이므로
    「감정평가에 관한 규칙」 제14조·제15조에 따라 분리평가하였습니다. 토지는 공시지가기준법을 기준으로
    삼되, 「상속세 및 증여세법」 제60조의 시가를 확인하기 위해 거래사례비교법을 병행하여 결정단가를
    도출하였고, 건물은 원가법을 적용하였습니다. 수익환원법은 적용하지 않았습니다.</p>
  <div class="method-list">
    <div class="method-item selected">
      <div class="method-badge">1</div>
      <div>
        <h3 class="method-name">토지 — 공시지가기준법</h3>

          “감정평가법인등은 법 제3조제1항 본문에 따라 토지를 감정평가할 때에는 공시지가기준법을
          적용해야 한다”고 규정합니다. 인근 표준지공시지가를 기준으로 시점수정·지역요인·개별요인·
          그 밖의 요인 보정을 거쳐 시산가액을 산출하고, 거래사례비교법 시산가액과 교차 검토하였습니다.</div>
      </div>
    </div>
    <div class="method-item selected">
      <div class="method-badge">2</div>
      <div>
        <h3 class="method-name">토지 — 거래사례비교법 (결정단가 도출)</h3>
        <div class="method-reason">… 본 사례의 토지 결정단가 8,350,000원/㎡은 이 방법으로 산출하였습니다.</div>
      </div>
    </div>
    <div class="method-item selected">
      <div class="method-badge">3</div>
      <div>
        <h3 class="method-name">건물 — 원가법 (잔가법)</h3>
        <div class="method-reason">「감정평가에 관한 규칙」 제15조는
          “감정평가법인등은 건물을 감정평가할 때에 원가법을 적용해야 한다”고 규정합니다. …</div>

          구분소유권의 대상이 되는 건물은 같은 규칙 제16조에 따라 토지와 건물을 일괄하여
```

`.method-name { font-size:14px; font-weight:700 }` 덕분에 **픽셀 단위로 동일**합니다.
추가되는 것은 질문형 `<h2>` 한 줄과 요약 단락뿐입니다.

### 6-3. 삭제되는 것 — 숨김 키워드 스팬

v1 `about-appraisal` 섹션에 있는 다음 마크업은 **v2 에서 전면 제거**합니다.
```html
<span style="color:var(--bg);font-size:1px;"> 강동구 성내동 감정평가 재개발 감정평가
근린생활시설 토지 건물 감정평가 거래사례비교법 원가법 공인 감정평가법인
강동구 토지 시세 성내동 재개발구역</span>
```
제거 사유 2가지:
1. **효과가 음(−)입니다.** Keyword Stuffing 17.7% < 기준선 19.3%. 넣을수록 인용 확률이 떨어집니다.
2. **Google 스팸 정책 위반 위험.** 배경색과 같은 색 + 1px 폰트는 Google Search Essentials 의
   "Hidden text and links" 에 정면으로 해당하며, 수동 조치 대상입니다.

CLAUDE.md §1 의 `SEO 키워드 숨김 span: color:var(--bg); font-size:1px;` 규칙은 **v2 에서 폐지**합니다.
대체 수단은 **본문에 실제로 보이는 문장**입니다 — `근거 법령 및 출처` 섹션, `법인 소개` 섹션, 질문형 `h2` 가
같은 키워드를 자연스럽게 담습니다.

## 8. 게시 전 체크리스트 (publish_case_v1.py 가 실제로 막는 항목)

`automation/publish_case_v1.py` 의 `validate()` 게이트 + v2 추가 게이트입니다.
**하나라도 실패하면 `automation/rejected/` 로 이동되고 게시되지 않습니다.**

### 스크립트가 강제하는 게이트
- [ ] `<!DOCTYPE html>` 선언이 있다
- [ ] `<html lang="ko">` 가 있다
- [ ] **`<h1>` 이 정확히 1개**
- [ ] **`<h2>` 가 3개 이상** (v2 템플릿은 12개)
- [ ] **JSON-LD 3블록이 모두 JSON 으로 파싱된다** — `Article`, `FAQPage`, `BreadcrumbList` 전부 존재
- [ ] **canonical 이 `https://gaachi.co.kr/cases/<slug>.html` 과 일치**
- [ ] 개인정보 패턴 없음 — `(의뢰인|소유자|신청인)\s*[:：]\s*[가-힣]{2,4}` 불검출
- [ ] `automation/config/blocklist_names_v1.txt` 의 인명 불검출
- [ ] **금지 문구 불검출** — `수수료`, `평가수수료`, `비용은 약`
- [ ] **`<\!--` 오타 없음**

### v2 추가 게이트 (사람이 확인)
- [ ] `<h3>` 이 1개 이상 (템플릿 기본 12개)
- [ ] `<p class="lead-answer">` 직답 단락이 h1 바로 뒤에 있고, 최종액·기준시점·평가방법·법인 정식명칭+소재지 4요소를 모두 포함
- [ ] **숨김 키워드 스팬 0건** — `font-size:1px` 또는 `color:var(--bg)` 인라인 스타일 불검출
- [ ] FAQ 질문이 **JSON-LD ↔ 본문 `<h3>` 글자 단위 완전 일치** (4쌍)
- [ ] `og:url`·`hreflang`·BreadcrumbList 4단계 `item` 이 canonical 과 동일
- [ ] `<link rel="alternate" type="application/rss+xml" href="https://gaachi.co.kr/feed.xml">` 존재
- [ ] `article:modified_time`·`dateModified`·본문 `<time datetime>` 최종 업데이트가 **모두 같은 날짜**
- [ ] `{{ }}` 미치환 토큰 0건
- [ ] 마스킹: 본건 호수 `███호`, 본건 층수 `제█층`, 지번 `███`, 전례 기준시점 연도만, 전례 목적 `—`, 비교사례 층수 삭제
- [ ] 법인 정식명칭 `㈜감정평가법인 가치앤같이` 가 6회 이상, `본 법인`·`당사` 0건
- [ ] 관련 사례 링크의 `/cases/*.html` 이 **실제로 존재하는 파일**
- [ ] 상속 전후 6개월 / 증여 전 6개월·후 3개월 표기가 정확
- [ ] 인용한 조문 번호가 §4 표와 일치 (임의 조문 금지)

### 자동 검증 명령
```bash
python3 -c "import json,re,sys; \
h=open(sys.argv[1],encoding='utf-8').read(); \
b=re.findall(r'<script[^>]*application/ld\+json[^>]*>(.*?)</script>',h,re.S); \
[json.loads(x) for x in b]; \
print('JSON-LD',len(b),'blocks OK'); \
print('h1',len(re.findall(r'<h1[\s>]',h)),'h2',len(re.findall(r'<h2[\s>]',h)),'h3',len(re.findall(r'<h3[\s>]',h))); \
print('hidden spans',len(re.findall(r'font-size\s*:\s*1px',h))); \
print('unfilled tokens',len(re.findall(r'\{\{[A-Z0-9_]+\}\}',h)))" 사례파일.html
```

파일이 생기기 전까지 이 링크는 404 를 반환합니다.
